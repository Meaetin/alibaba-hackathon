Organized as a Next.js App Router segment under `src/app/itineraries/` with four route handlers:
- `layout.tsx` wraps all children in `MainLayout`, providing shared chrome.
- `page.tsx` is the authenticated itinerary list: it fetches data via `useItinerariesQuery`, renders an optimistic bento grid of `ItineraryCard`s, and integrates an async job queue (`useJobsQueue` for `itinerary-planning`) so in-flight jobs appear as `ItineraryQueueCardItem` before being swapped in by an optimistic `buildOptimisticItinerary` row keyed on itinerary id. Creation goes through `createItineraryRouted` from `@/lib/api/itineraries`, with quota enforcement via `useQuotaGate` and `UsageCard`.
- `[id]/page.tsx` is the heavy interactive detail/editor page. It owns edit-mode state (`editLocalDays`), uses `@dnd-kit/core` sensors and collision detection for Kanban-style day/activity reordering, merges server realtime updates into a working copy via `mergeServerDaysPreservingPending` to preserve pending `temp-` activities, and coordinates side panels, transport mode changes, overlap deconfliction, flight/lodging PDF import, attachment management, and a dynamically imported `MapContainer`. Data comes from `useItineraryDetailQuery`, `useItineraryRealtime`, and Supabase queries; mutations go through `@/lib/api/itineraries` and `@/lib/supabase/queries/home`.
- `public/[token]/page.tsx` is a read-only view fetched via `getPublicItinerary(token)` from `@/lib/api/itineraries`, rendering a banner, header metadata, and per-day activity lists without auth.
Dependency direction is one-way: routes depend on shared hooks (`@/hooks/queries/*`, `@/hooks/use*`), UI primitives (`@/components/ui/*`), and API clients (`@/lib/api/*`, `@/lib/supabase/*`); they do not export reusable logic beyond React components.
