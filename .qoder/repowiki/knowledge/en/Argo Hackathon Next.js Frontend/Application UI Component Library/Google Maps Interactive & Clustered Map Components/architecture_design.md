The module is organized as a layered set of React components built on `@vis.gl/react-google-maps` (`APIProvider`, `Map`, `AdvancedMarker`, `Polyline`) and Next.js client-side patterns.

- Entry/wrapper layer: `MapContainer.tsx` is the public facade used by pages. It lazily loads `GoogleMapDetail` via `next/dynamic` (ssr: false), defers rendering until the container enters the viewport using `useIntersectionObserver`, shows a loading placeholder, and tracks map load events via `trackMapLoad`. It also hosts an optional `eager` mode for off-screen panels.
- Core interactive map: `GoogleMapDetail.tsx` renders the full `Map` with bounds fitting (`MapBoundsController`), numbered day-colored stop pins (`StopPin` SVG), default pin markers, route polylines with white-casing + colored overlay, hover popups (`LocationHoverDetailsPopup` or lightweight `MapNameBubble`), and place search integration through `MapSearchController` and `MapSearchRunnerProvider` which expose a viewport-biased search runner and Place Details fetcher to parent components via callbacks.
- Clustered view: `StaticMap.tsx` is a separate entry point for cluster-only maps; it lazy-loads `GoogleMapCluster.tsx`, manages its own hover state, and shares the `MapClusterData` type.
- Marker sub-components: `GoogleMapCluster.tsx` wraps clusters inside `APIProvider`, computes auto center/zoom from cluster bounds, and renders `AdvancedMarker` + `MapClusterMarker`. `MapClusterMarker.tsx` uses `class-variance-authority` variants for size/state/variant styling and composes `MapMarkerHover.tsx` for compact hover badges. `MapNameBubble.tsx` is a minimal name-only bubble used when `hoverVariant="name"`.

Dependency direction is one-way outward: this module depends on shared UI primitives (`cn`, `next-themes`), calendar palette utilities (`getDayPalette`, `PALETTE_COLORS`), and the `@/lib/maps/place-search` API; it exposes typed props (`MapLocation`, `MapPolylineSegment`, `MapClusterData`, `GoogleMapDetailProps`) so consumers never touch the Google SDK directly.
