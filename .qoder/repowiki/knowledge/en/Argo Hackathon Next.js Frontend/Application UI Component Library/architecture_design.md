The `src/components/` tree is organized as a layered design system: `primitives/` provides theme-driven base components (Button, Input, Sheet, Popover, etc.) built on Base UI + Tailwind + class-variance-authority; higher-level feature folders (`cards/`, `detail-views/`, `itinerary/`, `map/`, `modals/`, `navbar/`, `auth/`, `layout/`, `dashboard/`, `calendar/`, `links/`, `notes/`, `skeletons/`) compose those primitives into domain-specific UI. Cross-cutting concerns live at the top level: `QueryProvider.tsx` wraps the app in TanStack Query's `QueryClientProvider`, `ThemeProvider.tsx` wraps it in next-themes configured to force light mode via the `class` attribute, and `notifications/ItineraryJobNotifier.tsx` listens to Supabase realtime events to surface background job status. A barrel at `ui/index.ts` re-exports only the most-consumed symbols (cards, badges, breadcrumbs, collapsible, check button, detail fields) while most imports go directly to subpaths like `@/components/ui/primitives/Button`. Feature folders communicate by importing shared primitives and utilities rather than each other, keeping the hierarchy strictly bottom-up from primitives → feature components → page-level layouts.
