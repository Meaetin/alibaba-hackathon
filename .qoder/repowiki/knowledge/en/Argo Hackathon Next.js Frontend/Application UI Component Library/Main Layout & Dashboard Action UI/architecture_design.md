Two sibling sub-packages with distinct responsibilities:
- `layout/MainLayout.tsx` is a client component that wraps page content in a stack of providers (`NavigationLoadingProvider`, `NavbarFilterProvider`, `RightSidebarProvider`) and owns global state: profile loading via Supabase auth, navbar hide/show hysteresis driven by `ResizeObserver` + scroll thresholds, and three global modals (`NewLinkModal`, `NewCollectionModal`, `NewItineraryModal`). It renders the `Navbar`, a scrollable `<main>` slot, and a conditional right sidebar that switches between an inline `motion.div` column (when `presentation === 'inline'`) and a `Sheet` overlay below lg breakpoints. Cross-cutting side effects (toast notifications, query invalidation, custom events like `argo:content-prepended`) are dispatched from here after creating links/collections/itinerities.
- `dashboard/` contains small, composable primitives consumed by listing/detail pages: `ActionCard` and `CreateCard` are presentational cards built on `class-variance-authority` variants; `ActionToolbar` is a fixed bottom-centre floating bar for rubber-band selection that merges collections and itineraries into a single searchable `Popover` menu (with inline create-collection flow); `CardActionMenu` and `ListingContextMenu` are per-card kebab/right-click menus powered by `@base-ui/react/popover` positioned at absolute `(x,y)` coordinates, with visibility gated by `Record<ListingCardType, boolean>` tables.
Dependency direction is one-way outward: layout depends on shared contexts, modals, and API clients; dashboard primitives depend only on design-system primitives (`Button`, `Popover`, `Menu`, `SearchBar`) and `lib/utils` — they own no business logic or data fetching.
