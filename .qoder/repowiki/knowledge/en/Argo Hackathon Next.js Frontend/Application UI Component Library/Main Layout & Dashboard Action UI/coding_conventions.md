- Per-card and listing menus are implemented as controlled `Popover.Root` components whose trigger is a zero-size absolutely-positioned div at supplied `{x,y}` coords, enabling both kebab-button and right-click activation from the same component.
- Visibility of menu actions is declared declaratively via `Record<ListingCardType, boolean>` lookup tables (e.g. `showAddToCollection`, `showDelete`) rather than ad-hoc conditionals, keeping card-type behavior centralized.
- Styling uses Tailwind utility classes composed through `cn()` plus `cva` variant maps, with CSS custom properties (`--motion-duration-*`, `--motion-ease-*`, `--navbar-height`) driving transitions instead of hard-coded values.
- Global user feedback follows a uniform pattern: show a toast via `useToast().showToast`, optionally with `variant`, `title`, `description`, `action.label/href`, and `duration`, while errors are surfaced through `getFriendlyApiError`.
- Side effects that mutate remote state (create collection/itinerary/link) invalidate relevant React Query keys via `queryClient.invalidateQueries({ queryKey: queryKeys.*() })` and broadcast a `CustomEvent('argo:content-prepended')` so other views can prepend the new item without re-fetching.
- Components expose optional callback props to opt into features (e.g. `onGenerate`, `onDelete`, `onCreateCollection`, `onSaveToItinerary`) and render those sections only when the handler is provided, keeping each primitive usable in minimal contexts.
