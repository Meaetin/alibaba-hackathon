The module is organized as one file per resource domain (itineraries, collections, content, profile, photos, maps, flights, lodgings, locations, feedback, itinerary-notes, attachments) plus a shared `client.ts` core. `client.ts` provides the authentication boundary: `getAuthToken()` pulls an access token from Supabase Auth, `authFetch()` injects it into every request against `NEXT_PUBLIC_API_URL`, and `unwrap`/`ensureOk` centralize error handling by throwing typed `ApiError`s with numeric HTTP status codes. Domain files import these primitives and expose plain async functions whose signatures encode the server contract via exported TypeScript interfaces (e.g. `Itinerary`, `CreateActivityPayload`, `QuotaStatus`). Specialized error classes (`AlreadyAnalyzedError`, `LinkQuotaError`, `ItineraryQuotaError`) are thrown for business-level failures so callers can branch on error type rather than string messages. Some endpoints bypass `authFetch` when they need custom behavior — `attachments.ts` uploads directly to Supabase Storage then calls the backend to register the row, and `photos.ts` uses a process-scoped in-memory `Map` cache keyed by region/country/seed to avoid repeated Unsplash lookups.
