The module is organized as a staged pipeline with one responsibility per file, all sharing the shared schema in `types.ts` (`PreferenceProfile`, `CandidatePlace`, `PlaceEnrichment`, `SchedulerOptions`). Dependency direction flows inward: `funnel.ts` orchestrates stages by composing `score.ts` (Stage 3 scoring + hard filters), `cluster.ts` (Stage 4 k-means++ geographic clustering), and `taxonomy.ts` (static Interest→Google Places type/query bridge). `duration.ts` provides an independent visit-duration resolution ladder consumed later by the packer. The funnel enforces a strict narrowing order — hard filters → per-cluster cap → global cap with restaurant/cuisine quotas — and exposes `stages`/`stats` for replayability. Degradation ladders (`selectMealCandidates`, `widenBudget`) guarantee no day fails even when constraints are tight. Randomness is injected via an `rng` parameter to keep k-means reproducible; no ambient state or LLM calls exist inside this module.
