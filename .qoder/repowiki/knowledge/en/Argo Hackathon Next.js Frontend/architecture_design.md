The root configures the build and runtime contract that all child modules share: `next.config.js` enables strict mode and image remote patterns for Supabase/Unsplash; `tsconfig.json` sets strict TS with `@/*` path mapping to `src/`; `vitest.config.ts` runs colocated `*.test.ts` files via Vite with tsconfig paths. The app is split into four sibling layers under `src/`: `app_routes` (Next.js App Router pages), `components_ui` (React component tree), `hooks_contexts` (client state & data hooks), and `lib_core` (domain types, Supabase/REST clients, TanStack Query setup). Pages import from `components_ui`, which in turn consume `hooks_contexts` and `lib_core`; `lib_core` is the only layer that talks to Supabase or the external API, so cross-child communication flows top-down through typed props and React Query cache rather than direct coupling. Environment variables are documented in `.env.local.example` and consumed via `NEXT_PUBLIC_*` across children.
