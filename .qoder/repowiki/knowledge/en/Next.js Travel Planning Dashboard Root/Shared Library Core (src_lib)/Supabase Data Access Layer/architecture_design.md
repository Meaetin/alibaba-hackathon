The module is organized as a thin data-access layer over `@supabase/ssr`'s `createBrowserClient`, exported from `client.ts` so callers inject a `SupabaseClient` into each function. Queries are split by domain: `queries/` holds feature-specific modules (`home.ts` for recent content and itinerary detail, `search.ts` for RPC-backed full-text search, `location-references.ts`, `map-clusters.ts`, `recentlyViewed.ts`), while shared cross-cutting helpers (profile fetches, `content` detail, `collection_locations` upsert, and the reusable `getCollectionPreviewImages` helper) live in `queries.ts`. Mutations are isolated under `mutations/recordView.ts` and write to `recently_viewed` using Supabase RLS via `auth.getUser()`. Dependency direction is one-way: feature query modules import shared helpers from `../queries`; nothing in this package imports from UI or page layers, keeping it framework-agnostic and testable by passing in a mock `SupabaseClient`.
