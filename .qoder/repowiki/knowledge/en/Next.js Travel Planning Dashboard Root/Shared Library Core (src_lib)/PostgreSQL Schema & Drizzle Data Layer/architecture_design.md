The module is organized into four cohesive files re-exported from `index.ts`:
- `schema.ts` is the single source of truth for every table (`locations`, `place_search_cache`, `place_enrichments`, `area_guides`, `itineraries`, `itinerary_days`, `itinerary_activities`, `jobs`) defined via Drizzle's `pgTable`, with column types mapped to TypeScript through `$type<>` and JSONB fields typed against domain interfaces from `@/lib/planner/*`.
- `client.ts` provides a process-wide singleton `getDb()` (lazy-initialized from `DATABASE_URL`) and a test-friendly `createDb(connectionString)` factory; both return a Drizzle instance bound to the schema so all queries are type-safe.
- `stores.ts` implements the `SearchCache` and `LocationStore` ports declared in `@/lib/planner/retrieval`, exposing `createSearchCache(db)` and `createLocationStore(db)` so callers swap between in-memory and Postgres backends without changing call sites. It includes narrow patch methods (`updateShortlistHydration`, `updatePhotoResolution`) that preserve enrichment data on upserts using `coalesce` and conditional updates.
- `time.ts` centralizes the minutes-from-midnight time format used by `itinerary_activities.start_min` / `end_min`, throwing on out-of-range values rather than rendering incorrect times.
Dependency direction is one-way: `stores.ts` depends on `schema.ts` and `client.ts`; nothing in this module imports application logic, keeping it a pure persistence layer.
