The module implements a strict left-to-right pipeline with one responsibility per file, all sharing the domain schema in `types.ts` (`PreferenceProfile`, `CandidatePlace`, `PlaceEnrichment`, `SchedulerOptions`). `funnel.ts` is the orchestrator: it composes `score.ts` (Stage 3 scoring + hard filters), `cluster.ts` (Stage 4 k-means++ geographic clustering producing `PlaceCluster`), and `taxonomy.ts` (static `Interest → Google Places type/query` bridge). The funnel enforces a fixed narrowing order — hard filters → per-cluster cap → global cap with restaurant/cuisine quotas — and returns `stages`/`stats`/`dropped` for replayability. Degradation ladders (`selectMealCandidates` dietary ladder, `widenBudget` budget widening) guarantee non-empty results even when constraints are tight. `duration.ts` provides an independent visit-duration resolution ladder consumed later by the packer. Dependency direction is inward: only `types.ts` is shared; stages never call each other except through the funnel entry point. There is no ambient state, no LLM calls, and no network I/O inside this module.
