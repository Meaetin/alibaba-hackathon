The module is a flat collection of presentational React components plus small utility modules, all marked `"use client"` so they can be rendered on the server but interact in the browser. High-level composition lives in `ItineraryPageHeader.tsx` (banner + title + kebab menu) and `ItineraryControls.tsx`, which expose a controlled `viewMode: 'view' | 'edit'` prop; in edit mode the controls swap DataPills for an `ItineraryTabBar` whose tabs are defined in `tabs/` (`FlightTab`, `LodgingTab`, `BookingsTab`, `ExpensesTab`, `NotesTab`). The main editing canvas is `ItineraryEditLayout.tsx`, a three-column flex layout with draggable resize handles between left (day list), center (details panel, animated via `motion/react`), and right (map). Day rendering is split into `ItineraryDayColumn/` — `sequence.ts` builds a typed `DaySequenceItem[]` union of activities and transport legs from raw activity data, while `constants.ts` centralizes shared values like `INSET_PX` and the `TransportMode` enum. Supporting files provide cross-cutting concerns: `activity-utils.ts` for time parsing/formatting and lodging map building, `drag-utils.ts` for cascading day-time recomputation after reorder, `overlap-utils.ts` and `opening-hours-status.ts` for conflict detection, and `TimeBar.tsx` / `CompactActivityCard.tsx` / `ActivityThumbnail.tsx` as low-level visual primitives reused by the timeline. All components are stateless or controlled — business state and callbacks are owned by the parent page, keeping this module purely a UI layer.
