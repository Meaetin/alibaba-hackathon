The `src/components/` tree is organized as a strict bottom-up design system: `primitives/` exposes low-level, theme-aware building blocks (Button, Input, Sheet, Popover, etc.) built on Base UI + Tailwind + class-variance-authority; every higher-level folder (`cards/`, `detail-views/`, `itinerary/`, `map/`, `modals/`, `navbar/`, `auth/`, `layout/`, `dashboard/`, `calendar/`, `links/`, `notes/`, `skeletons/`) imports only from primitives and never from sibling feature folders, keeping the hierarchy one-directional. Cross-cutting concerns live at the top level: `QueryProvider.tsx` injects TanStack Query's `QueryClientProvider`, `ThemeProvider.tsx` wraps the app in next-themes configured to force light mode via the `class` attribute, and `notifications/ItineraryJobNotifier.tsx` subscribes to Supabase realtime events to surface background job status. A barrel at `ui/index.ts` re-exports only the most-consumed symbols (cards, badges, breadcrumbs, collapsible, check button, detail fields) while the rest of the codebase imports directly by subpath (e.g. `@/components/ui/primitives/Button`). Feature folders communicate exclusively through shared primitives and small utility modules (e.g. `itinerary/activity-utils.ts`, `itinerary/drag-utils.ts`, `cards/constants.ts`) rather than direct cross-feature imports.
