- Heavy Google Maps components are mounted lazily via `next/dynamic({ ssr: false })` and deferred until the container enters the viewport using `useIntersectionObserver`, showing a "Loading map..." placeholder while hidden.
- Map configuration (center, zoom, gesture handling, default UI) is computed locally per component — `getCenter`/`estimateZoom` for detail maps and `calculateMapView` for cluster maps — rather than passed down from parents.
- Theme-aware map selection reads `useTheme().resolvedTheme` to pick between `MAP_ID_LIGHT` and `MAP_ID_DARK` map IDs defined from `process.env`.
- Marker appearance is driven by `class-variance-authority` `cva` definitions keyed on `variant` (`by Country` | `by Collection` | `by Location`), `size` (`Small` | `Medium`), and `state` (`Default` | `Hover` | `Active`), composed with `cn` for final class strings.
- Asynchronous side effects that depend on the Google Maps context (place search, Places library availability) are isolated into small controller components (`MapSearchController`, `MapSearchRunnerProvider`, `MapBoundsController`) that consume `useMap()` and communicate results back to parents via refs to avoid unstable callback re-runs.
- Public component contracts are expressed as exported TypeScript interfaces (`MapLocation`, `MapPolylineSegment`, `MapClusterData`, `GoogleMapDetailProps`) and consumed by sibling components via cross-imports rather than global types.
