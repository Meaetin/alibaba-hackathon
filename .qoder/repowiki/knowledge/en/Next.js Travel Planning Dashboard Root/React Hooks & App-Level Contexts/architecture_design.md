Two sibling directories with a clear separation of concerns:
- `src/hooks/` contains pure, composable hooks. A `queries/` subdirectory groups TanStack Query wrappers (`useCollectionsQuery`, `useItineraryDetailQuery`, etc.) that thin around `@tanstack/react-query` + API functions and shared `queryKeys`. The remaining top-level hooks encapsulate side effects and DOM/browser APIs: Supabase realtime subscriptions (`useJobsQueue`, `useItineraryRealtime`), IntersectionObserver-based infinite scroll (`useInfiniteScroll`, `useIntersectionObserver`), media queries (`useMediaQuery`), animation/progress (`useProgressAnimation`, `useModalAnimation`), map interactions (`useMapClusters`, `useHighlightLocation`), and session/user helpers (`useSessionUserId`, useQuotaGate`).
- `src/contexts/` provides React `createContext` providers consumed via custom `useXxx()` hooks (`ToastContext`, `RightSidebarContext`, `NavbarFilterContext`, `NavbarVisibilityContext`, `NavigationLoadingContext`). Each context owns a small slice of global UI state (toast queue with timers, right sidebar content/presentation mode, navbar filter selection) and exposes typed setters.
Dependency direction is one-way: hooks may consume contexts (e.g. `RightSidebarProvider` uses `useBreakpoint` from `useMediaQuery`); contexts do not import hooks beyond `useContext`/`useState`. All hooks are marked `'use client'` to signal they rely on browser APIs or React state, and real-time logic subscribes to Supabase channels scoped per instance via `useId()` to avoid channel collisions.
