## System/Approach

This repository uses **npm** as its package manager for a Next.js 15 (App Router) frontend. Dependencies are declared in the root `package.json` and resolved via a committed `package-lock.json`, which pins exact versions for reproducible installs. There is no vendoring, private registry configuration, or monorepo tooling — it is a single-package project.

## Key Files

- `package.json` — declares runtime dependencies (`dependencies`) and development/test tooling (`devDependencies`). Notable runtime deps include `next`, `react`/`react-dom` (^19), `@tanstack/react-query`, `@supabase/supabase-js`, `@vis.gl/react-google-maps`, `motion`, `@base-ui/react`, `@dnd-kit/*`, `lucide-react`, `tailwind-merge`, `next-themes`, `react-day-picker`, and `tz-lookup`. Dev deps include TypeScript, ESLint, Vitest (+ UI), Tailwind CSS v4 with PostCSS, and Vite path resolution for tests.
- `package-lock.json` — committed lockfile that pins transitive dependency versions to guarantee deterministic builds across environments.
- `.gitignore` — excludes `node_modules`, `.next`, `out`, `.env.local`, `.DS_Store`, and `*.tsbuildinfo`; `node_modules` is never versioned.
- `next.config.js` — configures `optimizePackageImports` for `lucide-react` and `@base-ui/react` to reduce bundle size at build time.
- `postcss.config.js` — wires Tailwind CSS v4 via `@tailwindcss/postcss`.
- `vitest.config.ts` — sets up Vitest with `vite-tsconfig-paths` so tests resolve `src/*` paths identically to the app.

## Architecture & Conventions

- **Single flat dependency list**: All third-party packages are listed directly under `dependencies` or `devDependencies` in the root `package.json`. There are no workspace-level or per-package manifests.
- **Version pinning style**: Runtime dependencies use caret ranges (`^`) for minor/patch flexibility (e.g. `"next": "^15.1.0"`, `"react": "^19.0.0"`), while some critical libraries like Supabase SDKs are pinned to exact versions (`"@supabase/ssr": "0.5.2"`, `"@supabase/supabase-js": "2.89.0"`).
- **Lockfile-driven reproducibility**: The committed `package-lock.json` is the source of truth for installed versions; developers run `npm install` to honor it.
- **No vendoring / no private registry**: No `vendor/`, `third_party/`, or `.npmrc` files exist. All packages are pulled from the public npm registry.
- **Build-time optimization**: `next.config.js` explicitly lists `lucide-react` and `@base-ui/react` in `experimental.optimizePackageImports`, signaling a convention of keeping large UI/icon libraries tree-shaken into the bundle only where used.
- **Tailwind v4 migration**: The project has moved to Tailwind CSS v4 using the new `@tailwindcss/postcss` plugin rather than the legacy `tailwindcss` PostCSS plugin.

## Conventions & Constraints

- **Runtime vs dev separation**: UI/framework/runtime libraries live in `dependencies`; testing, linting, type-checking, and CSS tooling live in `devDependencies` — this keeps production builds free of test/dev tooling.
- **Node/React alignment**: The React and ReactDOM versions are pinned together (`"react": "^19.0.0"`, `"react-dom": "^19.0.0"`) and matched by `@types/react` and `@types/react-dom`, ensuring type compatibility.
- **TypeScript toolchain**: `typescript`, `@types/node`, and `tsc --noEmit` (via `npm run type-check`) are used purely for type checking; there is no TS-to-JS compilation step in the build scripts since Next.js handles it.
- **Test isolation**: Vitest runs in a `node` environment and includes only `src/**/*.test.ts` files; `passWithNoTests: true` allows adding tests incrementally without breaking CI.
- **Environment variables**: Secrets are not managed via dependency tools; `.env.local.example` documents required env vars while `.env.local` is gitignored.
- **No package-audit or update automation**: There is no `npm audit`, Dependabot, Renovate, or similar configured in this repo — updates are expected to be performed manually.
